# Аналитический контур v2 — подкатегории и связь с document-daemon

Актуально на 29 июля 2026 года.

Этот файл описывает не весь CRM-проект, а только модуль товарных подкатегорий для `Аналитического контура v2`.

## Что делает модуль

1. Хранит справочник категорий и подкатегорий в CRM БД:
   - `crm_product_categories`
   - `crm_product_subcategories`

2. Динамически строит фильтры страницы из БД:
   - верхний фильтр `Подкатегория`
   - sidebar-фильтр `Подкатегории`

3. Хранит связи `объект → подкатегория`:
   - `crm_object_subcategory_links`

4. Использует текущие факты из document-daemon и матчинга документов:
   - найденные материалы
   - найденные словосочетания
   - подтверждённые товарные группы
   - краткий контекст совпадений

## Главное правило назначения

Подкатегория не должна появляться “из воздуха”.

Порядок такой:

1. Сначала определяется товарная категория карточки из уже существующего слоя документов и матчей.
2. Только внутри этой категории подбирается подкатегория.
3. Если старая карточка ещё не получила корректную категорию от текущего контура/демона, подкатегория для неё считается неполной.
4. Для полного покрытия старого массива нужен отдельный перепрогон карточек через ИИ перед формированием карточек.

То есть:

- найденные материалы = факт;
- категория карточки = опора;
- подкатегория = уточнение внутри категории;
- массовый re-run ИИ = отдельный следующий этап.

## Как это связано с обработкой документов на 13-м

На сервере `S13` работают document-daemon процессы:

- `tender-docs-daemon-open`
- `tender-docs-daemon-awarded`

Они пишут результаты в:

- `tender_document_matches`
- `tender_document_match_details`

CRM-приложение на `S13:8504` читает эти данные через:

- `src/services/docs_match_preview.py`
- `src/services/objects_service.py`

После загрузки match-preview вызывается пересчёт связей:

`document daemon → tender_document_matches → apply_match_previews() → sync_for_items() → crm_object_subcategory_links → карточки v2`

## Какие файлы отвечают за этот слой

- `src/services/product_subcategories_service.py`
  - схема категорий/подкатегорий
  - seed стартовых подкатегорий
  - загрузка динамических фильтров

- `src/services/object_subcategory_links.py`
  - схема связей объект → подкатегория
  - правила сопоставления по фактам документов
  - загрузка связей для карточек

- `src/services/objects_service.py`
  - точка вызова пересчёта после загрузки объектов и документов

- `src/ui/analytics_contour_v2_page.py`
  - сборка карточек v2
  - чтение динамических фильтров из БД
  - применение связей объект → подкатегория

## Что уже считается динамическим

Если в БД добавить новую категорию или новую подкатегорию, страница должна подхватить её без отдельного хардкода в UI.

UI не должен хранить фиксированный список подкатегорий.

## Что уже заведено в seed-слое

- Светотехника
- Гидроизоляция
- Напольные покрытия

Для гидроизоляции первый слой подкатегорий построен по живым названиям и текущей логике контура:

- инъекционная
- обмазочная
- проникающая
- кровля и мембраны
- фундаменты и подземная часть
- паркинги и подвалы
- тоннели, мосты, путепроводы
- швы, вводы, коммуникации

Для полов:

- линолеум и ПВХ
- ламинат и паркет
- наливные и промышленные полы
- ковролин, спортивные и резиновые
- стяжка и подготовка основания
- общие напольные покрытия
